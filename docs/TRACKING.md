# Player and ball tracking

The tracking pipeline uses the existing YOLO26s checkpoint at 960 pixels. It calls the detector with a 0.10 person threshold so ByteTrack can associate lower-confidence detections; the ball retains the accepted 0.25 threshold. This differs from the detection evaluation's 0.25 global operating point. No model was retrained. `lap` supplies the assignment solver required by the pinned Ultralytics ByteTrack implementation.

```powershell
.\.venv\Scripts\python.exe scripts\track_video.py `
  --input 'E:\PitchLensStorage\footage\your-video.mp4' `
  --output 'E:\PitchLensStorage\outputs\new-tracking.mp4' `
  --weights runs\detection-baseline-640-v2\weights\best.pt `
  --config configs\tracking.json --device auto
```

The output directory must exist. Use a fresh name: the MP4, JSONL and summary JSON are never intentionally overwritten. MP4 output requires even frame dimensions and has no audio. Incomplete artifacts can remain if processing fails; choose a new name after examining them. `--device cpu` and `--device cuda` explicitly select the backend; `--max-frames` supports smoke checks. Processing is sequential, at the source frame rate. Variable-frame-rate timing is not represented.

Each JSONL line represents one zero-indexed frame, with `segment`, `camera_cut`, `tracks` and `ball_trajectory`. Tracks have `xyxy` coordinates in original-frame pixels, `class_id`, `track_id`, `confidence`, and `observed`. Identify people by the tuple `(segment, class_id, track_id)` within a video; IDs are restarted on cuts and new videos. Person tracks are only emitted when matched to a detection; a temporarily lost person may recover its ID but is not emitted during the gap. Class changes can produce a new ID. A ball has no persistent ID: predicted ball positions have `observed: false` and `confidence: null`; trajectory entries are `[x, y, observed]`. Green denotes observed ball positions, orange extrapolation. The tracker is initialized per video; API users must call `reset()` between videos and submit every frame in order at the declared FPS.

The ball starts at the highest-confidence candidate, then uses a constant-velocity prediction and selects candidates using confidence and distance within a frame-diagonal gate. It extrapolates for a bounded time and clears the trajectory when lost. ByteTrack score fusion is disabled so a consistent low-confidence new person can be confirmed using overlap. False positives can initialize or hijack a track, and fast motion, camera motion, occlusion or small detections can break it. The simple grayscale frame-difference cut heuristic resets all state on a sufficiently large change; it can miss cuts or mistake flashes and camera movement for cuts. Thresholds, time windows and gate size are configurable in `configs/tracking.json`. They are starting values, not validated optimal settings. No camera-motion compensation or re-identification is provided; ID switches remain possible, especially during occlusions. Quantitative tracking accuracy requires independently annotated footage.

## Team classification (experimental)

The video runner includes segment-local team assignments. `--team-config` optionally points to a JSON object overriding the defaults in `configs/team_classification.json`. Each JSONL track has `team` 1, 2, or null (unknown). Team numbers are arbitrary and may change across cuts or videos. Boxes are blue for team 1, magenta for team 2, and grey for unknown players and goalkeepers. Referees and balls have null team values. The model weights and tracker are unchanged.

The classifier samples the central torso, removes pixels resembling surrounding green pitch and likely skin, and clusters per-track smoothed LAB medians using two-means. It retains accepted centroids, expires inactive track colors, and attempts a matched refit when a cluster loses support and unassigned tracks accumulate. Very dark crops are ignored; recent track colors can bridge brief shadows. Insufficient crops, insufficient separation, and ambiguous or distant colors remain unknown. Goalkeepers always remain unknown; their team assignment was deferred until Feature #04, which is now authorized. API users must reset the classifier between videos; camera-cut segments reset it automatically.

This is a heuristic, not a calibrated confidence score. Crops can include other players and background, green or skin-colored shirts may be filtered, changing light and ID switches can confuse clustering, and a premature or incorrect two-cluster solution can assign wrong teams. Initial centroids and later refits can be wrong; matching team labels after a refit is heuristic. Referees misdetected as players can contaminate the fit. No manually labeled team ground truth was available, so accuracy is unmeasured. Similar-colored kits and green shirts close to the pitch color can remain unknown.

### Assisted team classification

The default runner uses automatic LAB clustering. To use manually selected representative crops, create a JSON file with non-empty `"1"` and `"2"` arrays of crop image paths, relative to that JSON file. Crops should show players from the respective teams. Pass `--team-references path/to/references.json --siglip-snapshot path/to/local/snapshot` alongside the tracking arguments above. The snapshot must contain the pretrained SigLIP model and processor configuration; loading is offline. Install the optional `assisted` project dependency in a compatible environment. Team labels are defined by the supplied references; assisted and automatic labels are not interchangeable.

The assisted mode batches embeddings every ten frames per player track, smooths them per track, and leaves players unknown until at least two observations support a sufficiently similar and separated prototype. These thresholds are starting values, not calibrated probabilities. It clears track history on cuts and retains the supplied team prototypes; create a new classifier per video. Goalkeepers and referees are not assigned. Poor references, tracking ID switches, small crops, occlusion, atypical lighting and false player detections can produce incorrect labels. The reference crops must be reviewed and exclude evaluation frames when measuring performance.
