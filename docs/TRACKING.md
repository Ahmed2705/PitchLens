# Player and ball tracking

The tracking pipeline uses [Candidate V2 and SoccerNet-v3D](DETECTION.md#default-video-detection). Candidate V2 runs at 640 pixels with a detection operating point of 0.25 and supplies people candidates down to 0.10. SoccerNet-v3D runs at 960 pixels with a detection cutoff of 0.15. The ball tracker keeps its 0.25 admission threshold.

Ultralytics BoT-SORT is the default for players, goalkeepers and referees. Each class has its own tracker. BoT-SORT receives the original BGR frame, including on frames with no detections, for sparse optical-flow camera motion compensation (`sparseOptFlow`). ReID is disabled. Association and motion compensation run on the CPU with either detector device. `lap` supplies the assignment solver.

The existing people thresholds apply to both backends. The low candidate floor is 0.10, the first-stage and new-track thresholds are 0.25, and the association threshold is 0.80. Lost tracks are retained for a one-second buffer converted to frames at the source FPS. Score fusion remains disabled. Use `--people-tracker bytetrack` or set `"people_tracker": "bytetrack"` in the tracking JSON to use ByteTrack. The CLI flag takes precedence over JSON. Existing tracking JSON files without `people_tracker` use BoT-SORT. The run summary records the active backend, motion compensation and ReID settings.

```powershell
.\.venv\Scripts\python.exe scripts\track_video.py `
  --input 'E:\PitchLensStorage\footage\your-video.mp4' `
  --output 'E:\PitchLensStorage\outputs\new-tracking.mp4' `
  --config configs\tracking.json --device auto
```

The output directory must exist. Use a fresh name: the MP4, JSONL and summary JSON are never intentionally overwritten. MP4 output requires even frame dimensions and has no audio. Incomplete artifacts can remain if processing fails; choose a new name after examining them. `--device cpu` and `--device cuda` explicitly select the backend; `--max-frames` supports smoke checks. Processing is sequential, at the source frame rate. Variable-frame-rate timing is not represented.

Each JSONL line represents one zero-indexed frame, with `segment`, `camera_cut`, `tracks` and `ball_trajectory`. Tracks have `xyxy` coordinates in original-frame pixels, `class_id`, `track_id`, `confidence`, and `observed`. Identify people by `(segment, class_id, track_id)` within a video. IDs are class-scoped and each new segment receives a numeric range above the IDs emitted in earlier segments. The new range carries no claim of player identity across shots. Person tracks are emitted when matched to a detection. A temporarily lost person may recover its ID after a gap in the same segment. Class changes can produce a new ID. The ball has no persistent ID. Predicted ball positions have `observed: false` and `confidence: null`. Trajectory entries are `[x, y, observed]`. Green denotes observed ball positions and orange denotes extrapolation. API users must call `reset()` between videos and submit every frame in order at the declared FPS.

The ball starts at the highest-confidence candidate, then uses a constant-velocity prediction and selects candidates using confidence and distance within a frame-diagonal gate. It extrapolates for a bounded time and clears the trajectory when lost.

In the prior two-clip evaluation using cached GSR player detections at 0.25, BoT-SORT produced longer observed tracks and recovered some earlier IDs after overlaps. The review also found an apparent ID swap after a crossing in FCB. False detections can acquire persistent IDs, and occlusion or class changes can fragment tracks. ## Hard camera cuts

The cut detector compares consecutive 160 × 90 color thumbnails. A substantial appearance change triggers a check for shared scene structure. It compares spatial luminance and chroma and looks for a pan or zoom supported by reversible optical-flow matches across the frame. When a sparse field view has too few corners, a translation check searches the center and edges in both directions and refines the match at OpenCV's interpolation precision. The translated overlap must agree both across the image and at its visible edges. A compact overlay and small accompanying graphics can change without ending the shot when most of the frame agrees and unchanged areas contain distinct two-dimensional features across several quadrants. Multiple large changes remain candidates for a cut. Alignment serves the cut decision. Track positions remain in image coordinates.

In the tracking configuration, `cut_appearance_threshold` defaults to 0.055 and controls the minimum normalized color change examined on textured frames. `cut_threshold` defaults to 0.32 for transitions between two low-detail frames. Keeping `cut_threshold` at 1.0 disables cut detection as before. Existing configuration files can omit the new field.

The first frame of a detected shot starts a fresh tracker for each person class, including new optical-flow history in BoT-SORT, and clears the ball position, velocity, gap counter and trajectory. The same cut flag clears automatic team history and centroids, assisted per-track observations, and pitch homography smoothing history. Assisted reference prototypes remain available. A ball or pitch result on the cut frame requires observations from the new shot. Gradual transitions, very similar camera angles, fast motion with little common image area, and heavy occlusion can still confuse the detector.

## Automatic team classification

The video runner defaults to `--team-mode siglip`. It samples up to 16 evenly spaced source frames within the analysis range, using the configured people detector on a separate capture. Per frame it retains up to 12 high-confidence outfield jersey crops after size, shape and overlap checks. Goalkeepers and referees are excluded. It mean-pools SigLIP vision tokens in batches of eight, fits three-dimensional UMAP with a fixed seed, and fits K-means with two clusters. Cluster means in normalized SigLIP space provide cosine-similarity and margin checks for subsequent track observations. This follows the SigLIP, UMAP and K-means fitting sequence from the [Roboflow Sports reference](https://github.com/roboflow/sports/blob/main/sports/common/team.py).

The two cluster identities are fixed for the analyzed clip, including across camera cuts. Uncertain observed players can supply new crops at least 12 frames apart. Two agreeing observations must pass the confidence and margin checks before the team is cached for that track. Camera cuts clear track evidence and retain the same clip-wide identities. In JSONL, Team A is `team: 1`, Team B is `team: 2`, and unknown is `team: null`. The default video displays Team A in blue, Team B in magenta and unknown players in grey. Goalkeepers, referees and balls remain unknown. Team identities are arbitrary across clips.

The model is [`google/siglip-base-patch16-224`](https://huggingface.co/google/siglip-base-patch16-224), revision `7fd15f0689c79d79e38b1c2e2e2370a7bf2761ed`, Apache-2.0. The verified Safetensors checkpoint is 812,672,320 bytes with SHA-256 `2c63cb7d1f2e95ba501893cbb8faeb4ea9a3af295498d35097126228659c2af8`. The local copy and its two configuration files are in `E:\PitchLensStorage\models\pretrained\siglip-base-patch16-224`. [Official weight metadata](https://huggingface.co/google/siglip-base-patch16-224/blob/7fd15f0689c79d79e38b1c2e2e2370a7bf2761ed/model.safetensors)

The existing environment already had PyTorch 2.11.0, Transformers 5.24.1, UMAP 0.6.0, scikit-learn 1.9.1 and Pillow 13.0.0. The `teams` packaging extra records the added direct dependencies. SigLIP uses the selected detector device, and UMAP and K-means run on the CPU. The tracking command above selects automatic SigLIP. `--siglip-snapshot` overrides the local directory. `--storage-root` changes the root for the standard model location. Missing weights or insufficient crops stop automatic initialization with an error.

Similar kits, lighting changes, partial bodies, detector class errors and ID switches can lead to wrong or unknown assignments. The clip must show both teams clearly enough for fitting. Fixed track assignments can preserve an error until a new track is created. This mode does not infer club names.

### Color fallback

Use `--team-mode color` for the existing segment-local LAB classifier. `--team-config` also selects color mode unless an explicit team mode is given, and overrides the defaults in `configs/team_classification.json`. Color team numbers may change across camera cuts or videos.

The classifier samples the central torso, removes pixels resembling surrounding green pitch and likely skin, and clusters per-track smoothed LAB medians using two-means. It retains accepted centroids, expires inactive track colors, and attempts a matched refit when a cluster loses support and unassigned tracks accumulate. Very dark crops are ignored; recent track colors can bridge brief shadows. Insufficient crops, insufficient separation, and ambiguous or distant colors remain unknown. Goalkeepers always remain unknown; their team assignment was deferred until Feature #04, which is now authorized. API users must reset the classifier between videos; camera-cut segments reset it automatically.

This is a heuristic, not a calibrated confidence score. Crops can include other players and background, green or skin-colored shirts may be filtered, changing light and ID switches can confuse clustering, and a premature or incorrect two-cluster solution can assign wrong teams. Initial centroids and later refits can be wrong; matching team labels after a refit is heuristic. Referees misdetected as players can contaminate the fit. No manually labeled team ground truth was available, so accuracy is unmeasured. Similar-colored kits and green shirts close to the pitch color can remain unknown.

### Assisted team classification

The default runner uses automatic LAB clustering. To use manually selected representative crops, create a JSON file with non-empty `"1"` and `"2"` arrays of crop image paths, relative to that JSON file. Crops should show players from the respective teams. Pass `--team-references path/to/references.json --siglip-snapshot path/to/local/snapshot` alongside the tracking arguments above. The snapshot must contain the pretrained SigLIP model and processor configuration; loading is offline. Install the optional `assisted` project dependency in a compatible environment. Team labels are defined by the supplied references; assisted and automatic labels are not interchangeable.

The assisted mode batches embeddings every ten frames per player track, smooths them per track, and leaves players unknown until at least two observations support a sufficiently similar and separated prototype. These thresholds are starting values, not calibrated probabilities. It clears track history on cuts and retains the supplied team prototypes; create a new classifier per video. Goalkeepers and referees are not assigned. Poor references, tracking ID switches, small crops, occlusion, atypical lighting and false player detections can produce incorrect labels. The reference crops must be reviewed and exclude evaluation frames when measuring performance.
